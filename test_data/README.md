# Test data

This directory holds the data the tests in `../autotest` read: for each
test domain, the model inputs and the reference answers (PRMS output).
Neither is tracked here. They come from the
[pws-prms-oracle](https://github.com/DOI-USGS/pws-prms-oracle)
repository and are placed under `test_data/<domain>/` by
`generate/oracle_populate.py`. See "Populating the data" below.

## Domain descriptions
The following are general descriptions of the test data domain directories.

### hru_1
This is the second (index 1 in python) HRU in the NHM CONUS domain. It is meant
to be small spatially but long in time. The record is 40 years. It tests
the NHM configuration with and without depression storage.

### drb_2yr
A test domain of smaller spatial size and 2 years duration. It tests the NHM
configuration with and without depression storage.

### ucb_2yr
A test domain of larger spatial size and 2 years duration. It tests the NHM
configuration with and without depression storage.

### sagehen_5yr
A test domain of small size and a 5 year duration. It tests HRU cascades
(the sagehen_no_gw_cascades.control file). With cascades turned off (the
sagehen_no_cascades.control file) the domain tests depression storage off,
dunnian flow and sroff in the soilzone, preferential flow, and pptmix in the
canopy (only depression storage off is tested by the other domains and
configurations).

### sagehen_gridded_5yr
A gridded version of sagehen (5609 cells, some inactive) over the same 5
years, with HRU cascades (the sagehen_gridded_cascades.control file). It
tests inactive-HRU masking and the cascade classes at scale. Its CBH
forcing files are generated by PRMS in the oracle, not distributed as
inputs.

### fgr_ag_2yr
An NHM extraction with irrigated agriculture (612 HRUs), 2 years. It
runs GSFLOW's AG package (a spinup control and an analysis control) and
tests the agriculture variants of runoff and soilzone.

## Populating the data

The answers are produced in the oracle repository, not here. Setup is
described in [`DEVELOPER.md`](../DEVELOPER.md), "Testing". In short:

1. Answers come from either a published oracle release (downloaded by
   `generate/oracle_fetch.py` into `test_data/.oracle/`; needs
   `GITHUB_TOKEN`, the repository is internal) or a local oracle clone
   (`PWS_ORACLE_DIR` pointing at its `domains/`).
2. `generate/oracle_populate.py` fills `test_data/<domain>/` from there.

What `oracle_populate.py` puts in `test_data/<domain>/`:

- Links to the oracle's inputs (`*.control`, `*.param`, `cbh.nc`,
  `parameters_*.nc`, ...). Copies on Windows without Developer Mode.
- One `output*/` directory per control file, with links to the answer
  netCDF files.
- Derived answer variables, written as regular files next to the links.
  These are pywatershed-specific (previous-timestep states, `*_change`,
  `through_rain`, `infil_hru`, `seg_lateral_inflow`, ...) and are
  computed by `generate/prms_diagnostic_variables.py`.
- Three markers: `.oracle_ikey` (inputs key), `output*/.oracle_okey`
  (answers key), both copied from the oracle, and `output*/.derived_okey`,
  the answers key the derived variables were computed from. The tests
  raise an error when `.derived_okey` and `.oracle_okey` differ: the
  answers changed, re-populate.

Options:

```shell
python generate/oracle_populate.py                      # every domain
python generate/oracle_populate.py --domain hru_1       # one domain
python generate/oracle_populate.py --domain drb_2yr --control_pattern nhm.control
python generate/oracle_populate.py --no-derive          # skip derived variables
python generate/oracle_populate.py --force              # replace existing regular files
```

Other scripts in `generate/` are not part of populating. They record how
the inputs were made and are run by hand when inputs change:

- `separate_params_to_nc.py` — writes `parameters_<Process>.nc` and
  `parameters_dis_*.nc` from a domain's parameter file.
- `prms_convert_to_netcdf.py`, `prms_diagnostic_variables.py` — PRMS
  variable naming and the derived variables; imported by
  `oracle_populate.py`.
- `cbh_to_nc.py`, `cbh_nc_indivual.py` — CBH text to netCDF.
- `transp_frost_params_to_existing_params.py` — adds frost parameters.
- `drb_2yr_subset.sh`, `conus_2yr_subset.sh`, `submit_domains_tg.sh` —
  how the 2-year subsets were cut from the full records.

## Domain directories

Additional domains may be supplied by the user for autotesting by
pywatershed. Also note that evaluation of pywatershed against PRMS in
the notebook `examples/03_compare_pws_prms.ipynb` uses this approach
as well. To supply your own domain, create `test_data/your_domain` with
the files a populated domain holds (see "Populating the data" above).

The `*.cbh` files must be pre-converted to netcdf for `prcp`, `tmin`,
and `tmax`. How to do this can be found near the top of notebook
`examples/02_prms_legacy_models.ipynb`. The `*.control` and
`myparam.param` files are used by both PRMS and PWS. The `*.control`
files in the repository are specific for being able to run sub-models in
pywatershed and include a nearly maximal amount of model output
(time-inefficient for both PRMS and PWS but necessary or pywatershed
autotests). The stock control files can be found in `test_data/common`.
There is a file for single-HRU domains and multi-HRU domains and these
are identical (as appropriate) for the domains included in the
repository.
